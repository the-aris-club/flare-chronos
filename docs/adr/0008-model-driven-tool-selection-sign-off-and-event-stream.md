# 0008. Model-Driven Tool Selection, Tiered Tool Surfaces, Human Sign-off and an Event Stream

**Status:** accepted

**Extends:** [ADR-0005](./0005-dual-system-langgraph-harness-and-deterministic-tool-gate.md) and [ADR-0006](./0006-explicit-endpoint-profiles-and-grounded-narrative-assembly.md)

The Dual-System harness gives the language model the objective and the rules, not a step-by-step plan. The System 2 Deliberative Layer chooses its own deterministic tool calls from an exposed surface. The System 1 Reflexive Layer becomes the tier that reports rather than the tier that routes by regex. A briefing that authorizes an operational action pauses for a human sign-off. The whole run is observable as a typed event stream that a web client can consume over Server-Sent Events.

## Context & Trade-Offs

After ADR-0006 the harness bound each layer to a model and grounded the narrative, but two things were still off.

**The routing was regex, not reasoning.** `_system1_triage_node` derived the region, the epochs, and the cognitive path from regular expressions over the raw query, and the System 1 model was never consulted on the fifteen deliberative use cases. The architecture in ADR-0005 says System 1 prunes the tool surface for System 2; in practice a regex did the pruning and the model stayed silent. The tier boundary was therefore asserted rather than measured.

**The tool plan was written by the harness, not the model.** The harness decided which tools a use case called and synthesised their arguments. The model contributed a reasoning trace and nothing else. That is safe, but it wastes the capability the endpoint was bought for, and it makes the System 2 Deliberative Layer a formatter rather than a reasoner. We rejected the alternative of free model choice as well: letting the model pick arguments would make the tool arguments, and therefore the recorded facts, non-reproducible.

**There was no place for a human.** A field alert and a tactical dispatch are the two outputs a human must answer for. Nothing in the harness could pause, ask, and resume.

We also rejected building the agent loop on `create_react_agent`. It is deprecated in the installed `langgraph-prebuilt` in favour of `create_agent` from the `langchain` package, which would add a dependency whose middleware system this harness would barely use, and it would fight the custom state the harness carries. `ToolNode` plus `tools_condition`, which LangGraph documents for custom workflows, is already installed, already used, and keeps full control of the state.

## Decision

1. **The model chooses the tools.** System 2 receives the deterministic tool surface and decides which tools to call and with which arguments, in a loop that ends when it stops calling tools. The harness bounds the loop with a reasoning-step budget and falls back to the deterministic formatter when the budget is exhausted.
2. **The tier is defined by the tool surface, not by a use-case list.** The System 1 Reflexive Layer reaches only the Atomic Tools, so the tier that reports can never reach a derivation. The System 2 Deliberative Layer reaches the Atomic Tools, the Domain Diagnostic Tools, and the clarification tool. The raw FIRMS slice harmoniser stays outside the registry and outside the model's reach.
3. **System 1 classifies before it routes.** The triage node asks the classifier for the region, the urgency, and whether the request is deliberative, and merges the answer into the entity. The model's answer may override the inferred cognitive tier only when the operator did not name a use case; an explicit use case always wins. The Reflexive Layer may speak either the typed-questions protocol, whose answer carries a calibrated probability, or the native chat protocol, where the model answers through a structured classification tool and its confidence is self-reported. The harness records which of the two produced the answer, so a self-reported estimate is never read as a calibrated one.
4. **The System 1 fast tier stays a single hop.** The fast tier executes one Atomic Tool and returns a grounded fact card. It never writes an analytical narrative, and it asks no model to write: a fact card is a formatted tool output, so the tier answers without a language-model turn.
5. **Guidance moves into a system prompt.** The domain brief, the tool discipline, the citation protocol, and the clarification rules live in one prompt per tier, in the spirit of a coding agent's system prompt. The harness no longer scripts a step-by-step plan into the conversation. The prompt also carries the stakeholder tier, so the narrative leads with what that reader needs: the operational implication for a ranger, the magnitude and its policy consequence for an executive, the mechanism and its assumptions for a scientist.
6. **The model is told to stop.** An early revision told it to call as many tools as the question needs, and it did: one use case burned eight tool rounds and ended on the deterministic floor. The discipline now says to start with the tool that matches the use case, to call the smallest set that answers the question, and to stop once the output answers it.
7. **A deliberating model that says nothing is asked again.** A model in a thinking mode sometimes stops without emitting a tool call or any content. The adapter detects that and repeats the call without deliberation, which always produces a turn.
8. **Sign-off suspends the run.** A use case listed in `requires_sign_off` pauses at a sign-off gate through LangGraph's `interrupt`. The run resumes with the human's answer. A rejected sign-off releases no briefing; the decision is recorded either way.
9. **Clarification is a tool, not a special case.** The model may raise a clarification request through a tool that interrupts the run. It is bounded, and it authorizes nothing. A clarification is answered automatically only by a batch run, never a sign-off.
10. **The run is an event stream.** The harness exposes typed events, and an SSE encoder turns them into frames. A paused run is one segment of the stream; the human's answer starts the next segment with the same thread identifier.
11. **The durable checkpointer is injected.** The harness accepts a checkpointer, so an offline test injects an in-memory one and a sign-off run injects the SQLite one, which lets a paused run survive a process restart.
12. **Retries are bounded and selective.** A model node retries a transport failure, a rate limit or a server error, and never a client error. The deterministic tool node caches its result, because a tool's output is a pure function of its arguments.
13. **The classifier is not a single point of failure.** A rate-limited classifier would otherwise kill every run at its first node. The classification is an enhancement over the provisional extraction, so an unavailable classifier degrades to it and records why.
14. **A model is chosen by measurement, not by name.** The Reflexive Layer and the Deliberative Layer each run the whole live benchmark against every candidate the provider offers, and the winner is the model that verifies the most use cases with the fewest repairs, the fewest clarifications, and one tool round each. The Reflexive Layer therefore classifies with a small model that is exact and fast, and the Deliberative Layer writes with the model that needs no repair. A model name is configuration, never code, so the choice is reversible.
15. **A deliberation level belongs to one model family.** One candidate refused the configured level and answered every request with an error. A model that refuses the level is asked again without deliberation instead of losing the run, the refusal is remembered for the following turns, and the telemetry reports that the tier ran without deliberation so no report overclaims it.
16. **The Reflexive Layer assigns the analysis.** The layer names the one analysis of the twenty that a request needs, and that answer decides the tier, the tool surface, the cache key and the report title. A use case written by the operator always wins; the model's assignment is used when the request names none. The menu of twenty analyses is one list, shared by the typed-questions payload and the chat tool, so both protocols answer in the same shape.
17. **The classifier answers first, the text extraction answers last.** The Reflexive Layer runs a chain: the decision model first, then the chat model, then the deterministic extraction. Every step down is recorded, so a report never claims a classification that did not happen. The chain exists because the analysis assignment and the region are the two facts the text extraction gets wrong: on indirectly named places it answered three of eight correctly where the model answered eight of eight, and the analysis it stamped was a fixed one.
18. **The decision model is served locally, and the harness is calibrated to it.** The decision endpoint answers typed questions with calibrated probabilities, which the harness compares against thresholds taken from measurement rather than from a default. The tier threshold is the last-resort rule because the model's deliberative probability does not separate the two tiers; the analysis assignment does. The urgency threshold sits in the middle of the measured gap between the urgent and the calm requests, which keeps the margin wide when the calibration drifts. The decision model runs on the project's own inference node, so the Reflexive Layer spends no cloud credit and keeps working when a hosted service does not.

## Consequences

- The routing decision and the extracted entity now carry a calibrated probability instead of a regex match, and the classification is recorded in the run state and in the telemetry.
- The narrative is authored by the model against the tool surface the tier allows, and the numbers in it are still injected by the harness.
- The two tiers are separated by something observable: the tools each of them can reach.
- A briefing that authorizes a field action cannot be released without a recorded human decision, and a declined briefing is not published.
- A web client can stream the run and answer a pending request without the harness knowing anything about HTTP.
- The live suite depends on a model that emits tool calls reliably. The offline suite cannot exercise that path, because a model cannot be simulated faithfully; the offline suite instead drives the scripted agent.
- A node timeout is not available: LangGraph supports per-node timeouts only for asynchronous nodes, and the harness nodes are synchronous. The endpoint profile's own timeout bounds the model call instead.
- The provider offers several models on the same free plan, and only the decision-capable ones are billed. Every model was measured on the same twenty use cases, so the choice rests on a measurement rather than on a reputation. The Reflexive Layer classifies with the model that answered twenty of twenty requests exactly in under two seconds; the Deliberative Layer writes with the model that needed no repair and no clarification across the whole benchmark.
- A run can complete without deliberation when the endpoint refuses the configured level. The telemetry says so, and the narrative that results is still checked against the Verified Facts Ledger.
- One failing measurement no longer removes the whole batch: the symbiosis measurements are isolated, and the benchmark records the failure and continues.
- A paused run is resumed from a checkpoint on disk, not from memory, so a sign-off that waits for a ranger overnight survives a restart of the process. The claim is now covered by a test that resumes the run from a second harness on the same file.
- The Reflexive Layer earns its place by naming the analysis, not by reading the region off the query. A request that names no use case used to be stamped with a fixed one, and that stamp reached the report title and the cache key; the layer's own answer now replaces it, and a live test holds the assignment in place.
- The Reflexive Layer's own call earns its place on the region as well. On requests that name a place indirectly, the text extraction answered three of eight correctly and the model answered eight of eight. Without that call a request about Manaus would have run on the Mekong data, and nothing would have raised an error.
- The Reflexive Layer stays a separate tier even with one model behind it, because the reporting tier answers without a model at all: zero tokens, zero credit, zero variance between runs, and no dependency on the provider being up. The seconds a provider takes are its own property and move with its load, so they are not a reason to keep a tier; the fact that a call is made at all is.
- A model's measured latency is a property of the provider and of the serving stack on the day of the measurement, not a property of the model. Latency is therefore recorded as an observation and never used to choose a model. The criteria are the ones that belong to the model: correctness on the project's own requests, the tokens it reads and writes, and whether it emits the tool call it was asked for.
- The calibrated-probability claim describes the running system again. The Reflexive Layer's primary classifier is a decision endpoint, so its confidence is calibrated and the telemetry records the source as such. When the chat model answers in its place, the source is recorded as self-reported, and when no classifier answers, the source is recorded as none. No report presents one as another.
- The Reflexive Layer now runs a chain of classifiers, and the run state records which one answered. When the decision endpoint answers, the confidence is calibrated and the source says so; when the chat endpoint answers, it is self-reported; when neither answers, the deterministic extraction stands in and the reason is recorded.
- The decision model is served by the inference node's own Ollama, not by a hosted endpoint. It answers the typed-questions protocol locally, so the layer costs no cloud credit and keeps working when the hosted service does not. The node's Ollama had to be upgraded for the decision-capable weights to load at all: the old build refused the model outright.
- The text extraction is no longer the source of the region or the analysis when a classifier answered. It remains the floor: it is what the run uses when every classifier is unavailable, and it is what the fallback degradation is measured against.
- The thresholds are measurements, not defaults. The deliberative threshold is the last-resort rule because the model's deliberative probability overlaps the two tiers, and the urgency threshold sits in the middle of the measured gap so that a drift in calibration does not flip a request.
